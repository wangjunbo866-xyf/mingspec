# Specification Home and Migration

按当前操作读取对应章节，术语与写入边界见 [Shared Boundaries](shared-boundaries.md)。

## Canonical Home

在目标项目使用 `mingspec/specs/<domain>/<module>/spec.md` 作为当前主规格，同模块 `patches/<patch-id>/spec.md` 作为候选。域按长期职责，模块按可独立描述和验收的能力划分；实际名称、ID 和职责从目标读取，不按 Skill 或命令数量预建模块。

一个跨模块目标归一份主责 Patch，引用全部受影响规则。可分别交付验收的目标才拆开并说明真实依赖。每条当前规则只有一个权威归属，共享规则用引用。根/域/模块索引复用既定 README/readme 文件名，不并列建两套导航，分层职责见 [Business Map](business-map.md#discover-the-map)。过程知识在目标 `mingspec/runbook/`。

首建主规格版本为 current-v1，已有模块独立续版；迁入时保留原版本及规则映射，模块版与 Skill/包版本区分，不称重新实现或验收。按[分档](patch-workflow.md#choose-the-change-tier)处理小修；新功能先写候选，既有行为补档按 [First Specification](business-map.md#first-specification)。旧位置仍有当前资料时走迁移，不建重复正文。历史外部资料和已吸收 Patch 可保留原位并注明历史身份。新候选不要求 OpenSpec 格式、proposal 或兼容增量。

## Independently Readable Main Specifications

使用[主规格模板](../assets/main-spec.md)的阅读结构：Scope、Terms and Model、Dependencies and Shared Rules、Behavior、Interfaces and Compatibility、Sources。可按实际需要合并或简写，既有正文只增量维护本次内容，模板不授权批量重排。区分覆盖范围、不覆盖项与已知缺口；术语、对象、状态就地定义或明确引用。没有独立接口可并入行为，不适用说明依据，未知保持缺口。

本主规格及明确公共引用须让未参与开发者判断当前覆盖范围的正常、异常、边界和兼容行为。写清主体、前提/触发、输入、可观察结果及适用场景，按需覆盖失败、重复操作和状态边界。依赖指向具体规则/定义并说明适用行为及作用范围，逐层展开至可判断。循环、冲突、歧义和缺失定义列为相关缺口，不能用互相引用代替完整规则。

吸收时把完整当前条件放入主规格或明确公共引用；历史只作决定和证据追溯，逐规则保留来源，不要求读者拼接历史增量。未交付目标留候选，并由模块入口导航。

## Independent Reading Check

先按 [Change Tier](patch-workflow.md#choose-the-change-tier)确定是否需要独立审查。小修由执行者核对受影响正文和来源，不强制本检查。标准/完整档首建或修订主规格时，将本检查与最终差异审查合并为一次，由同一位未参与修改者完成并留一份记录：

1. 先只读拟交付的当前主规格及明确公共引用，暂不读历史 Patch、任务证据或实现。在受影响范围从当前契约选择正常、异常、边界和兼容输入，不给期望答案；简要记录判断、依据及无法判断项。可审拟吸收的完整正文，不能只审 Patch 增量。
2. 首次判断记录后，同一评审再读来源、旧规则、实现及验证证据，核对完整最终差异、全部受影响条件/场景、稳定 ID、兼容和项目规范。主规格、Patch、地图与必要知识一并覆盖；不另安排第二位收尾评审或第二份报告。
3. 缺口未解不完成相关交付；修复后只补核受影响部分，在同一记录区分初读与复核。已读来源后的核对不能称新的首次阅读。可先审完整拟吸收候选，再按相同正文写回并核对字节；完全相同且无新影响时直接复用，改变候选才按影响补审。

已有独立审查只有在覆盖本次主规格正文、来源对账和最终差异时才算完成合并检查；否则补缺失部分，不机械重开全套。评审已读来源而尚无初读记录时，应如实保留缺口，改由未接触来源者完成未覆盖的阅读部分，不冒称盲读。只有明确要求或具体风险需要才增设额外独立检查并说明原因，跨模块本身不增加收尾轮次。检查不授予新的实施、批量整理或发布权限。

## Small-Step Maintenance

沿根→域→模块定位本次规则及存在时的 Patch，写前读全受影响条件、例外、场景及共享约束；发现依赖、冲突或跨模块影响再扩展。检索只用于定位，不默认读全仓历史，也不凭片段改写。以一个可独立验收目标演进，按完整已验收规则吸收，单个场景通过不等于整条规则交付。

Ming Spec 起草/修订候选或维护主规格时检查相关主规格当前行数；Ming Archive 检查拟写入完整正文的预计行数，写后复核实际行数。首次尚无主规格时说明事实，不造占位文件，首次吸收前再统计拟正文。

超 300 行时报告路径、当前/预计行数、职责是否混杂及拆分建议或保留理由。按独立能力判断边界，内聚规则可保留超限；未超限但职责混杂也可建议拆分。提醒不判失败、不自动迁移或重复审批。授权内拆分按迁移流程，保全条件、例外、场景、ID 和来源，不用挤行或藏必要规则规避。查询只读，结论留原任务。

物理行包含空行、表格、代码、元数据；LF/CRLF 都按换行计数，未换行的末尾非空行计一行，结尾换行不多加一行。已有文件可调用：

```sh
python3 "<product>/scripts/mingspec" spec-size --root "<project>" --spec mingspec/specs/<domain>/<module>/spec.md
```

产品路径从实际 Skill 解析，项目路径从明确目标读取。命令只统计指定现存文件，不计算拟合并正文；拟正文按同口径完整统计。没有 Python 时可按该口径手工计数，说明工具未运行。命令参数、只读范围及退出码见 [Size Command](../../../USAGE.md#main-specification-size)。

## Migrate an Existing Project

1. 确认迁移/接入授权；仅写 SPEC 不授予整批迁移权限。清点目标入口、主规格、原始需求、在途/历史、附件、验收与工具消费者，区分现存、删除、缺失、未跟踪和并行资料。记录 HEAD 与实际工作文件依据，HEAD 不替代未提交原文。
2. 在原任务记录旧/新位置、逐规则与场景映射、版本、稳定 ID、来源、原字节校验值和可取回原件。域/模块按真实职责划分，保留唯一当前正文；已吸收历史不因分域自动拆散。检查同名、大小写、真实路径、越界链接、硬链接及解码冲突，冲突先保留现场。
3. 迁移现存资料，写前重核并行变化，保留业务语义、版本、范围、未决项和候选/历史状态。缺失仍缺失，不从 Git、案例或安装副本自动恢复，不借迁移重发历史任务。
4. 切换受影响当前双向导航、相对链接、锚点、配置和工具消费者。旧历史路径通过原任务映射追溯，原始日志不改写。仍需兼容的入口引用同一正文或明确生成投影，记录使用者与退出条件并验证发现；不另建第二套规则，不默认留无用途跳转壳。
5. 对照实际文件与原件核对全部规则、条件、例外、场景、ID、引用、工具行为和适用回归，交未参与修改者独立复核。检查失败/原有缺口分别报告；链接通过不代表语义或业务验收，当前维护不要求 OpenSpec 校验投影。
6. 检查和复核完成才切换根入口为已迁移，执行下节退出步骤，报告实际状态和未验证项。已迁移则允许零差异；缺授权或材料可只读回答，不称接入完成。迁移不等于业务实施、全局安装、提交或部署。

CLI init 只补空框架，不能证明调查、迁移或知识整理完成，不在已有准确结构上重复初始化。

## Retire Migration Artifacts

清理前逐项确认有效信息已承接、实际原件可读且字节/校验一致、当前引用与工具依赖已处理、迁移检查与独立复核完成，以及有效清理授权。满足后按用途删除无使用者的旧正文/配置/兼容投影、重复快照和临时材料及空目录；不按文件名批量删除，也不要求等待上线、固定天数或另一次提交。

保留独立历史 Patch、原始证据、唯一来源和仍有使用者的入口。原任务记录删除清单及保留用途，临时保留项说明解除条件；缺口只阻塞相关清理。只有规则更新或只读查询时不执行删除，去向记录不是删除许可。清理后复查入口与链接，重复收尾允许零差异。
