# Specification Home and Migration

## Canonical Home

采用 mingspec 后，当前规格使用 `mingspec/specs/<domain>/<module>/spec.md`，后续候选使用主责模块的 `patches/<patch-id>/spec.md`。业务域围绕长期职责，功能模块围绕可独立描述和验收的能力划分；名称、稳定 ID、业务规则与工作区约定从目标读取，Skill、CLI 和插件不决定域/模块。一项目标跨模块或跨域时只在主责模块维护一份 Patch，并引用全部受影响规则；能分别交付和验收的目标才拆分并说明真实依赖。

分层地图复用根、域和模块各自的索引（如 README.md 或 readme.md）；建立或维护索引时，必须按 [Business Map](business-map.md) 的分层职责、唯一入口与状态归属执行。过程知识继续放 `mingspec/runbook/`，外部来源和已吸收历史 Patch 可保留原位并标明历史身份。

模块主规格按范围、稳定规则块和来源组织；候选沿 [五章模板](../assets/spec.md)，任务和证据按授权与实际需要维护。新建模块主规格首版为 `current-v1`，已有独立模块版本按真实修订接续，与 Skill 方法版本和产品包版本分开；从旧总规格迁入时明确原版本、规则映射和可取回原件，不能把新版本编号称为重新实现或重新验收。每条当前规则只有一个权威归属，跨模块通过引用使用。当前流程不要求 OpenSpec 的格式、命令、proposal 或兼容增量；保留的历史工具产物不承担新候选职责。规格模板来自真实 Skill 安装位置，不能将安装副本当目标正文。

首次尚无规格时，按 [First Specification](business-map.md#first-specification) 区分新增功能与既有行为补档：新功能先建 Patch 内候选，验收后建立主规格；既有行为可直接补录经核对确认的范围基线。已存在其他位置的规格时，进入下列迁移；不能因为目标目录为空就另起第二套正文。只读查询可沿现有来源回答并指出尚未迁移，不执行 init 或移动资料。

## Independently Readable Main Specifications

首建或修订模块主规格时，读取 [Main Specification Template](../assets/main-spec.md)，按范围、术语与模型、公共依赖、行为、接口与兼容、来源组织。章节可按实际需要合并或简写；既有规格只对本次受影响内容补齐，保留稳定 ID 和旧链接。新功能仍先写 Patch，首建主规格沿既有验收门槛；模板不改变当前/候选身份。

当维护已有主规格时，Ming Spec 或 Ming Archive 应沿目标已采用的章节结构，将本次有依据的完整规则及场景并入对应行为块，并按影响更新范围、术语与模型、公共依赖、接口与兼容及来源。候选 SPEC 的五章用于组织本次变更，不直接搬成主规格章节。当模板修订而本次未授权章节调整时，执行者应保持目标既定结构，只补齐本次受影响内容。

读者应能只凭本主规格及明确引用的公共规格，判断当前覆盖范围内正常、异常、边界和兼容行为。按规则写清主体、前提/触发、输入、可观察结果及适用场景；未知列为缺口，不适用说明依据。明确覆盖能力、不覆盖项和已知缺口；必要术语、对象与状态关系就地定义或引用公共定义，接口约束可并入对应行为。

公共依赖指向真实文件与具体规则/定义，说明适用行为、条件及作用范围；继续展开必要依赖直到相关结果可判断。循环、缺失或冲突不能由相互引用掩盖；公共规则只维护一份权威正文。历史来源放规则末尾或 Sources，保持逐规则可追；有效行为应在主规格或其明确公共引用中，不能要求读者从历史 Patch 拼出当前规则。未交付目标留候选并由模块入口导航。

## Independent Reading Check

首建、修订主规格的完成检查及收尾的最终独立审查均执行本步骤，只覆盖本次受影响规则和必要共享依赖；记录复用原任务/证据位置。

1. **先独立阅读。** 由未参与该部分修改者只读主规格与明确列出的公共规格，暂不读历史 Patch、任务证据或实现代码。按公开契约选择正常、异常、边界和兼容场景输入，不向评审者附期望答案；记录其预期结果、正文依据、适用性和无法判断项。公共引用有缺失、冲突或循环且无法确定结果时，记录具体依赖缺口。
2. **再对账来源。** 首次阅读记录完成后，再读来源 Patch 和原规则，逐项核对本次受影响条件、场景、稳定 ID 与兼容约束。特别检查来源中仍有效但当前正文或公共引用遗漏的行为；能靠历史推断答案不算正文完整。
3. **补齐并复核。** 将缺口交回规格维护，在授权范围补齐主规格或具体公共引用；必要缺口未解，仅暂停相关交付/吸收，不声称完成。修复后重核受影响内容，并区分首次阅读与已知答案后的复核，不冒充新的首次阅读。

完成条件：本次适用场景都有从主规格或明确公共规格取得的可判定结果，来源对账无未解语义遗漏；不适用有依据、缺口及阻塞真实。链接/结构检查不能替代这项检查或业务验收，原验收及独立审查门槛继续适用；本步骤不授权实施或批量改写无关旧规格。

## Small-Step Maintenance

沿根→域→模块先定位本次规则与 Patch，完整读取受影响规则的条件、例外、场景和共享约束；发现依赖、冲突或跨模块影响再扩展阅读。检索用于定位，不以片段代替完整规则；不默认加载全仓主规格或历史。演进继续以单个可验收目标为 Patch，独立交付的目标才拆开；吸收以完整已验收规则为单位，未交付候选继续保留。

Ming Spec 起草/修订候选或维护主规格时检查相关主规格当前行数；Ming Archive 吸收前对拟写入的完整正文计数，写后复核实际行数。首次尚无主规格时说明事实，在首次吸收前统计拟正文，不为统计建立占位主规格。

主规格超过 **300 行**时，报告路径、当前/预计行数及职责评估，给出按独立能力划分的拆分建议或保留理由。按物理行统计，包含空行、元数据、表格和代码，LF/CRLF 均按换行计数，末尾非空且未换行计一行，末尾换行不多算一行。当前文件可从完整产品安装位置运行：

```sh
python3 <product>/scripts/mingspec spec-size --root <project> --spec mingspec/specs/<domain>/<module>/spec.md
```

`<product>` 由本 Skill 真实路径上溯到产品根，`<project>` 是目标项目；不要把示例当现成路径。该命令只统计指定主规格，不计算候选合并结果。预计行数从拟吸收的完整正文计算，不能只将新增行数相加；没有 Python 时由 Agent 按同一口径计数，并说明工具未运行。

以可独立描述、交付和验收的能力判断拆分，300 行是评估触发点，不是上限；内聚规则可说明理由后保留，未超限但职责混杂也可建议拆分。结果简记原 Patch/已有记录；查询只读报告。提醒不判失败、不自动迁移，也不新增审批；实际拆分复用有效授权并按下节迁移，缺少授权时保留建议。保留完整条件、例外、场景和稳定引用，不靠挤行、删规则或将必要规则藏入附件缩短主规格。

## Migrate an Existing Project

1. **确认来源与权限。** 从 AGENTS/README/现有地图清点当前主规格、原始需求、在途和历史变更、验收/交接证据、附件、引用和工具路径配置；区分现存、已删除、外部历史、未提交及并行工作。记录实际 HEAD 和工作文件快照，不能用 HEAD 覆盖尚未提交的内容。只有写规格的授权不能推定允许整批迁移；用户已明确授权接入迁移或本次移动时直接复用。
2. **确定映射。** 按职责将现有当前规则和在途 Patch 映射到上述域/模块/patches 布局；总规格拆分时逐规则核对完整条件、例外与场景，明确唯一归属及跨模块引用。保留稳定 ID、原版本/新模块版本、状态和来源，已吸收历史 Patch 不因分域而拆散。检查目的地及祖先实际路径、大小写碰撞、未知文件、符号链接越界或共享硬链接；冲突先保留现场，只暂停依赖步骤。已有已授权目录迁移不逐文件重新审批。
3. **保存可取回原件。** 清单记录旧/新路径、实际基线及原字节来源/校验值。历史收据含旧路径或授权范围时保留逐字原件；当前定位投影只作一一映射，保留确认来源，不把移动等同重验、授权扩展或重发历史任务。
4. **迁移唯一正文。** 移动现存资料，写前重核快照避免覆盖并行编辑；保持业务条款、未决项、有效覆盖、候选/历史状态不变。已删除资料仍缺失，不从 Git 或案例自动恢复。历史外部档案原位保留；缺失引用转为明确历史路径/缺口说明，不能编造替代来源。
5. **切换引用与工具。** 同步 AGENTS、分层地图、当前双向链接、相对资源链接、配置和机器路径投影；不能仅替换字符串而漏掉相对引用。核对旧格式/工具约束是否仍为当前要求，保留必要验证的实际覆盖，不能用新链接通过代替场景和语义核对。旧地址通过原任务中的映射追溯，不默认生成跳转壳或继续维护失去用途的工具投影；仍有必要使用者时记录具体保留用途。保留原始历史含义，不能为清理路径重写旧结论。
6. **验证并独立复核。** 核对清单与实际文件、规范化路径后正文差异、来源/原件、链接及 HTML/标题锚点、实际工具消费者和相关回归；仍保留的兼容入口也纳入验证，失败/既有缺口分别记录。再独立检查全部旧规则和场景去向、强约束未丢、无两份当前正文、未误恢复删除，记录实际候选与结果。没有自动覆盖的部分使用实际逐项核对和独立审查，不称未实现的检查器已通过。
7. **收尾。** 只有切换与检查完成才将根入口标记为已迁移；必要原→新映射、旧基线和未验证事项归入已有变更/任务记录，按 [Retire Migration Artifacts](#retire-migration-artifacts) 核对临时材料退出。后续新增和修订只从 mingspec/specs 进入。已准确迁移时允许零差异，不重复备份/迁移；缺少授权或资料时仍可只读回答，不宣称接入完成。

CLI `init` 始终只补缺失空骨架，不预建业务域、模块或主规格，不能以它成功证明上述迁移完成。仍必要的工具若要求旧路径，兼容入口只引用同一正文或明确生成投影，并记录使用者及退出条件；必须验证实际发现，不能静默漏验新 Patch。迁移不包含业务实施、全局配置、提交、合并、发布或部署。

## Retire Migration Artifacts

迁移收尾时按用途核对旧总主规格、失去使用者的工具配置/兼容投影、迁移说明、压缩包及重复快照；名称不是固定必备文件，也不能作为批量删除依据。

1. 确认新入口和本次迁移检查/独立复核已完成；将临时材料中仍有效的约定、必要映射、来源与未决事项并回已有正文或任务记录。
2. 实际读取既有 Git 版本或任务证据，核对原文可取回且字节/校验值一致；尤其不能用 HEAD 代替迁移时未提交的工作文件。不以新建备份目录替代已有来源核对。
3. 查清引用和工具依赖，更新或移除当前指针。上述条件满足且已有迁移收尾/清理授权覆盖时，应删除已失去用途的旧正文、配置/兼容投影、重复或临时材料和因此变空的目录，再检查链接与入口；不默认留下导航壳。独立历史 Patch、业务原始需求、唯一原件和确有使用者的入口按用途保留。
4. 原任务简记实际删除与保留清单；每项保留说明具体用途，临时保留项说明解除条件。无需等待业务上线、固定天数或另一次 Git 提交，不另建退出报告、索引或汇总页。

完成条件：有效信息和原件仍可追溯，当前入口没有断链，临时材料已按条件清理或有具体保留原因；只更新约定或只读核对不触发实际删除，重复收尾保持零差异。
