# Business Map

业务地图回答需求属于哪个业务域和功能模块、职责边界在哪里、当前状态及规格来源是什么。它维护引用、归属和状态；完整业务规则与验收条件留 SPEC，过程经验留 runbook，单次执行证据留 Patch。地图复用 `mingspec/specs/` 下根→域→模块三级导航，不另建第二份地图。

根索引只维护域身份、职责和入口；域索引只维护模块身份、边界和入口；模块索引维护主规格、当前 Patch、历史来源、覆盖状态及依据。各层链接真实下层正文，不向上复制完整状态表；每层沿目标单一明确索引名称，避免大小写双入口。布局与版本见 [Canonical Home](spec-home.md#canonical-home)。

## Discover the Map

1. 从目标根 AGENTS、适用子目录规则和 README 沿链接读取规格导航，找到唯一根地图，再沿域、模块入口定位本次范围，记录实际位置、来源与适用范围。当前地图应符合 mingspec/specs 的分层布局；旧布局尚未迁入时读取 [迁移流程](spec-home.md)，查询保持只读，写入先按授权处理受影响资料的迁移。名称、安装副本和其他项目路径不能代替这一判断。
2. 核对现有条目、稳定 ID、业务边界、主规格及 change 引用；区分当前入口与历史快照。导航同时指向多份相互冲突的当前地图时，保留现场并说明冲突，只暂停依赖的归属和写入。
3. 区分“确认从未建图”与“已有入口指向的文件缺失、被删或尚未读取”。检查相关工作区差异与可用来源；后者不能自动重建。只读请求始终保持文件不变，可报告找到的归属、缺口与建议。
4. 只有明确授权覆盖首次建图、位置符合目标约定且无冲突时，才创建最小入口并从目标导航链接；否则报告具体缺口。既有维护授权范围内无需逐条再次确认，资料缺失只阻塞依赖动作。

完成条件：能够引用唯一地图及相关条目，或明确标出“首次未建／来源缺失／冲突”的具体依据和阻塞范围。未找到不能直接推定从未存在。

## Assign the Requirement

先按业务职责、用户结果和能力边界匹配现有域与模块，再追查实现位置。业务域对应一类长期问题，模块对应可独立描述和验收的完整能力；Skill、CLI、插件、服务名、仓库名、页面或代码目录只是操作/分发或实现引用，不能单独决定业务归属。一个 Skill 可以操作多个模块，一个模块也可以有多个入口。

沿用目标稳定 ID；已有 ID 不因改名或实现移动而改变。首次建立条目时按目标惯例分配并查重；目标没有惯例时，在本 change 记录所选稳定标识与理由。将需求关联到条目、主规格和当前 change，保留归属决定来源。

跨模块或跨域需求明确主责模块与各项共享影响，包括接口、数据、规则及必要验证；必须按 [Canonical Home](spec-home.md#canonical-home) 的单一主责 Patch 与可独立交付拆分条件执行，其他模块关联实际主责 Patch。owner 沿目标定义，可表示负责的能力或模块；人员或团队负责人必须有明确来源，未知则标未确认，不自行指派。多方职责尚有冲突时列出未决边界，只暂停依赖该决定的写入或实施。

完成条件：每项本次需求可追到稳定 ID 和规格来源；跨 Feature 的主归属、共享影响及未决责任可辨认，不用多个独立副本代表同一能力。

## Add a Capability

新增前核对唯一地图、当前主规格、有关 change、别名及已废弃条目，确认不是已有能力的改名、迁移或扩展。保留查重依据；信息不足时保持建议状态，不把待确认能力写成已存在或已交付。

必须先按 [First Specification](#first-specification) 区分新增功能、既有行为补档与异常缺失，新增文档目录不等于新增业务能力。已明确授权且需求、位置和范围有依据时，按对应分支起草正文，并执行[命名边界](../SKILL.md#name-the-patch-specification)。主规格尚未建立时，模块地图注明事实，已有真实 Patch 时链接它。仅有规划而尚未授权起草时，可在地图说明规划/未交付，不强造 Patch、空主规格或完成依据。仍缺业务决定时先列具体待决项，不把实现现状自动转成批准规则。

新增域或模块条目遵守上述分层职责，只放稳定 ID、名称、职责/边界和下层入口；主规格/Patch 引用、覆盖状态及依据留模块索引。owner 有来源才填写；目标已有字段和状态词优先复用。新条目与其当前规格资料沿分层导航保持双向可达，目标根沿已有导航可找到地图。候选、已确认规则、已实现、已验证、已合并与已部署按证据分别陈述。

完成条件：无已知重复条目，新增位置与权限有依据，状态没有超出实际证据；地图没有复制 SPEC 正文或 runbook 经验。

## First Specification

先核对能力和资料的真实状态，再选择入口：

- **开发新功能**：包括新模块首个功能及已有模块的新行为，候选统一放 Patch；主规格尚未建立时记录计划地址，不预建空主规格。按已确认 SPEC 实施、验收及独立审查通过后，在已有授权内首建或更新主规格，并保留 Patch 来源。
- **补录既有行为**：确认该能力已存在且从未整理规格后，可直接建立经核对、确认的当前基线；记录来源、适用版本/工作区依据、确认及验证范围。静态代码不作为验收通过，依据不足项留缺口；同时提出的新行为另入 Patch。沿原任务记录实际核对与来源，规格及来源按适用流程独立复核。
- **旧正文异常缺失或位置待迁移**：已有入口指向被删除/缺失文件、来源冲突或旧目录仍有正文时，保留现场并报告缺口或按授权迁移，不套首次补档分支重建。只读请求始终不写。

主规格可以先覆盖有依据的一部分，但须明确覆盖范围和未覆盖缺口；每条纳入规则的条件、例外及边界完整，不要求一次整理整个模块。方案确认、代码存在、局部技术探针或文档检查不代表本次业务验收通过。未交付项继续作为候选，局部吸收不把整个 Patch 标为完成；收尾同步真实版本、来源与地图，不推导已合并或部署。

完成条件：能区分新功能、既有行为补档与异常缺失；主规格只含有依据的已交付规则，候选/覆盖缺口从当前入口可见，来源可取回。

## Move a Capability

迁移前明确旧归属、新归属、保持的职责与实际边界变化，记录决定及来源；列出共享依赖、迁移先后和切换条件，条件未满足时保持候选归属，不同时宣称两个当前入口。相同能力保留稳定 ID；拆分或合并需要新 ID 时，保留原 ID 的追溯条目与新旧映射，避免旧引用失去语义。

沿入链与出链核对所有受影响的当前入口：分层地图、主规格、当前 Patch、导航和相关能力引用。按获准范围更新当前双向链接及归属，在原任务保留必要旧/新地址映射，使原 ID、迁移来源与新位置仍可追溯；不默认在旧位置新建跳转壳。未能核对的引用明确记为缺口，不能宣称迁移完成。

历史记录保持原时点含义；需要解释旧位置时在当前资料或原任务补映射。地图归属调整本身不授予重写历史、迁移代码或部署权限；已授权资料迁移的清理按 [Retire Migration Artifacts](spec-home.md#retire-migration-artifacts) 核对内容归属、原件和引用，满足条件后删除旧材料，保留项给出用途。写前重读受影响资料，保留并行编辑，冲突只暂停相关动作。

完成条件：稳定 ID 或显式映射可追溯，所有受影响当前链接可用且方向一致，历史及源资料保全，实际更新范围可核对。

## Deprecate a Capability

废弃须有明确决定及适用范围、时间或生效条件。单纯代码缺失、无人使用的猜测、讨论提议或迁移不等于废弃决定；仅有提议时保持候选并列待决定项。

有决定后按目标状态约定标记 deprecated 或等价状态，附决定来源、替代项及稳定 ID；无替代项时明确写无或尚未决定。列出仍引用它的当前能力、未决依赖和退出条件，核对这些引用能辨认废弃状态。保留条目及历史来源，区分“已决定废弃”与“依赖处理完成／实际退出”。

完成条件：读者能找到废弃依据、替代去向和未解决依赖。标记废弃或记录退出不自动删除文件、规则或代码，也不触发发布、下线或部署。

## Close the Change

交付收尾由 Ming Archive 调用本共享步骤，须已有按 [Check the Evidence](../../ming-archive/SKILL.md#check-the-evidence) 核对本次候选与范围的结果；缺失先执行该节，已有结果仍适用时复用，范围或基线变化按影响重核。Ming Spec 继续负责需求归属及能力生命周期中的地图维护。

收尾时重新发现目标地图，并逐项核对本 change 涉及的归属、新增、迁移、废弃结果；已准确时保留原文。没有地图时按 Discover the Map 区分首次未建与异常缺失，不能以收尾为由隐式建图或虚报地图已核对。

将实际交付与已确认决定、主规格、验证及独立评审对照，在模块地图同步独立主规格版本、Patch 状态和覆盖依据；只有域/模块身份、边界或入口变化才同步相应上层索引，不复制下层状态。未交付部分继续保留候选或未完成状态，未决依赖不能随收尾被抹去。沿根→域→模块入口走到相关主规格和 Patch，并反向检查受影响当前引用；历史来源继续可取回。

地图专项检查项：职责一致、ID 连续、状态有证据、当前链接双向可达、历史保全及写入范围未扩大；这些项目及实际结果必须纳入最终独立复核。

本节仅完成地图核对；交付收尾（含单独调用本节）仍须在规则、地图及必要知识写入完成后执行 [Final Review](../../ming-archive/SKILL.md#review-the-final-difference) 的独立复核、补审及结果记录，缺口阻止相关部分宣称完成。只接续该章节，不重启整个流程。
