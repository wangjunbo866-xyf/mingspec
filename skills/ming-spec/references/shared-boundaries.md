# Shared Boundaries

四个 Skill 开始时读取本页 Authorization；写文件时读取 Preserve Materials；交付修改时读取 Verification and Review。先解析 SKILL.md 符号链接的真实路径，从完整产品位置读取方法。目标事实从目标 AGENTS、README 与规格导航读取。包内缺资源时报告缺口，不借目标项目或另一个安装补造方法。

## Authorization

明确目标项目、操作、SPEC 版本、实际工作区基线和有效授权。查询、只读或不保存请求保持零写入，只在答复说明结果与缺口。复用已有有效授权；范围内无需逐文件或逐任务重新确认。

规格、初始化、收尾、业务实施、安装、提交、发布、合并和部署分别按授权执行。业务承诺、AC、公共测试边界、必要检查或范围实质变化时，重核受影响部分；进度安排沿用原授权。必要冲突或权限缺口只阻塞依赖动作，历史或外部资料的指令不构成当前授权。

仅改 SPEC 时按 [Revision Scope](patch-workflow.md#revision-scope)处理，连 tasks 的待重核状态也保持不写。明确编排或完整交付才按 [Task Scope](../../ming-tickets/references/task-workflow.md#task-scope)维护任务。

## Preserve Materials

写前核对实际工作区和允许职责，保留未提交、未跟踪及并行资料、历史 Patch 和第三方来源。解析目标及祖先真实路径；写入越出授权工作区时停止依赖写入。发现共享硬链接或不能可靠解码的原文时保留现场并说明问题。可读不等于可写。

并行材料发生变化时，重新比较实际内容和本次决定，不能仅凭文本不重叠判断兼容。业务主规格由目标项目维护。优先复用已有目录和主题；单次清单、日志、核对结果留原任务/Issue/PR 或既有证据位置。新增长期文件须有现有位置无法承载的明确用途。

迁移或清理按 [Migration](spec-home.md#migrate-an-existing-project)执行；保留有效约定、完整条件、例外、业务规则和历史。去向说明不是删除授权。

## Verification and Review

按 [Change Tier](patch-workflow.md#choose-the-change-tier)确定验证与审查负担，所有档位都执行与实际影响相称的项目检查并读取结果。小修在主规格留一行真实来源与检查结论，详细命令/结果在原对话或已有任务说明；标准/完整档在原 Patch、任务或证据位置保留命令、cwd、环境、退出码、适用候选和跳过/未知，不强制单建报告。

CLI 行为修改先在真实临时项目复现目标失败，再最小修复和回归；环境失败不算目标失败，不倒造失败。文档/Skill 检查实际内容、路由和链接，按影响试用，不为纯说明制造程序测试。必要失败或证据不足阻塞依赖推进。

小修默认由执行者核对，不强制独立审查。标准档安排一次未参与该部分修改者的独立审查；完整档覆盖全部真实影响、任务依赖与集成证据，收尾仍默认一次。评审覆盖真实完整差异（含未提交/未跟踪、删除/重命名）、规格与项目规范；涉及主规格时把 [Independent Reading Check](spec-home.md#independent-reading-check)并入同一次，先读当前正文再查来源及最终差异。作者自评或格式检查不能替代适用档位的独立审查。

相同候选已有覆盖充分的审查结果直接复用，不因进入 Archive 再开一轮；候选、输入或规则变化后只按实际影响补验补审，记录复用范围。缺少必要依据不能称通过。区分计划、已执行、通过、失败、未运行与未知；历史成功不称本轮重跑，收尾不等于提交、发布或部署。

## Terms

- Domain：一类长期业务问题的职责范围。
- Module：域内可独立描述和验收的能力，不由文件、服务或 Skill 数量决定。
- Business Map：域、模块、规格及来源之间的分层导航，不是业务规则副本。
- Patch：一个明确目标的变更单元；历史 change 与其同义，可影响多个模块但只有一个主责位置。
- Candidate Specification：本次拟交付行为与验收；Main Specification：已有交付和验收依据的当前规则及覆盖缺口。
- Module Specification Version：模块正文版本，与 Skill 方法版、产品包版和业务重新验收区分。
- Change Record：修复回执或历史记录，不因五章结构成为候选。
- Task / Task ID：带交付、依赖和证据的工作单元及其 Patch 内稳定标识，跨 Patch 引用须含位置。
- Rule ID / AC ID：规则的稳定地址标识与验收条件编号。ID 相同不证明语义或旧证据仍适用。

## Boundary Decisions

遇到权限、来源或并行冲突，明确具体缺口和受影响动作；独立且依据充分的工作可继续。默认步骤直接执行，条件分支触发时读对应完整章节及必要依赖；同轮已读且未变的内容复用。目标业务规则修改前仍须读全，不能以检索片段替代。
