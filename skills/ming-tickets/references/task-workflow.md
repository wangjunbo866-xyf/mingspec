# Task Workflow

按当前操作读对应章节。公共授权、保护和验证要求见 [Shared Boundaries](../../ming-spec/references/shared-boundaries.md)。任务声明格式、旧文件兼容和检查失败处置见 [Run Task Checks](task-checks.md)。

## Task Scope

先按[分档](../../ming-spec/references/patch-workflow.md#choose-the-change-tier)判断需要：小修默认不建 tasks；标准档只有真实协作/依赖需要或明确编排请求才创建；完整档在交付授权内按真实依赖组织任务。维护同一主责 Patch 的 tasks.md 前说明写入目标，已有任务及历史保持，不因降档删除。查询只读，讨论或仅写 SPEC 不生成/改任务。整理任务不自动授权实施、全局安装、提交或部署。

复用原位置、任务 ID、历史与证据，不新增逐票目录、重复任务来源、调度器、强制 tracker 或独立 PLAN；任务文件不存在时按真实请求判断创建，不能把异常缺失当从未建立。SPEC-only 修订按 [Revision Scope](../../ming-spec/references/patch-workflow.md#revision-scope)报告影响而不写任务。

## Bind References

每项保留稳定任务 ID、交付摘要、可定位规则/AC或前置问题、真实阻塞 ID、执行边界、验证方法与状态/实际结果。业务规则由 SPEC 唯一表达，任务可写摘要、验证步骤和测试断言，不复制规范正文。

核对真实来源位置、已读版本或可取回基线及 ID；共用来源可集中，裸 ID 不是全局唯一。跨 Patch 引用带任务位置，编号顺序不是依赖。缺 AC 锚点使用实际章节及表格 ID，缺失/歧义交 Ming Spec，不伪造链接。

改标题、顺序、合并或退役时保持身份和历史可追；范围/禁止项引用 SPEC，再补本任务边界，文件清单不扩权。新任务用[模板](../assets/tasks.md)，旧版式只在转换授权内按检查指引迁移；未知或未执行保持真实状态。

## Decompose and Verify Locally

按可独立验证的纵向交付组织任务，覆盖该结果需要的层次。每个规则、AC 或前置问题须有可追溯任务或复用/延期/缺口说明。每项写清可验收交付、真实依赖、验证方式，完成前交付自身所需测试、文档和实际结果，不把局部欠账统一推给最终测试组。

检查缺失/歧义 ID、自依赖、循环、退役任务及旧基线结果。只有来源、权限和依赖适用的任务可开始；具体缺口只阻塞相关工作，顺序不能猜成依赖。必要失败、未运行或依赖不满足时保持未完成，不适用须有依据；不为无需要的任务强造层次、测试或文档。

跨任务集成在现有任务表记录集成检查及真实依赖，同时保留各项局部验证；局部通过不冒充整体通过。多调用方机械迁移按 [Wide Refactoring](wide-refactoring.md)判断原子替换或分批推进。

## Prerequisite Verification

当实施需要准备或关键假设尚未证实时，在同一 Patch 安排前置问题；无此依赖不强造实验。先明确问题/假设、环境/版本/输入、成功与失败判据、权限和数据影响，再执行已授权验证；规格授权不自动包含代码执行、服务操作、安装或数据写入。依赖未知结论的实施待定，已明确且无关工作可继续。

结果回原 SPEC：第二章记录观察与证据，第四章记可行性及设计/测试决定，第五章保留未决项/阻塞。技术判据与功能 AC 分开，实质变化同步受影响规则/AC并重核授权。只写 SPEC 时仅记录问题、判据和任务影响，不自动实验或建任务。

原始日志、脚本及探测证据留原任务/Issue/PR、既有证据或测试工具位置，通过 Patch 引用；不为验证另建 verification/ 或等效层级，位置不明先查目标约定。技术可行不等于功能交付，结论不能提前吸收为当前行为。

## Hand Off and Record

交接可读取的 tasks、SPEC/基线、项目入口、证据、可开始项和具体阻塞，记录实际执行方法来源/版本及适配，安装副本不等于历史方法版。提供解析后的任务检查命令、cwd 和原任务记录位置；另一机器重新解析产品根。

执行者读取实际材料后就近回写完成内容、检查结果、适用候选、证据和未决项，Ming Tickets 核对遗漏与一致性。每次状态回写后运行 [Run Task Checks](task-checks.md)。本项交付和适用检查有依据才标任务完成；不把 Patch 最终合并审查变成每个任务一次审查，项目明确要求任务级审查时仍遵守。单项完成不等于整个 Patch 验收或主规格吸收。

接手失败报告具体缺口，一次第三方调用成功不宣称普遍兼容；不绑定执行工具，也不要求新分支、工作树或自动 PR。

## Reconcile Results

规格、输入或实现基线实质变化时，对照新旧来源和真实下游，保留任务 ID、旧版本、原始完成证据，按影响决定复用、补验、补做或退役并记理由。获准写任务才标当前待重核；旧 completed/勾选只证明旧基线，不能释放当前依赖。相关后续等待结论，无关任务可继续。

同一规则/AC ID 变义也须重核，不因 ID 相同推定兼容。原候选或证据不可取回时保留缺口。仅措辞调整先核对语义与结果适用性再复用，不自动全量重拆或抹历史，事实与当前结论分别记录。补验补审沿公共验证要求执行，业务/设计新决定回同一 SPEC。
