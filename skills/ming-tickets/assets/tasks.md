来源：填写主责域/模块、同一 Patch 的实际 SPEC 地址、读取版本与可取回基线；多份 SPEC 分别记录来源，任务字段仍写实际相对文件位置。业务规则从 SPEC 读取，本文件是唯一任务来源。

范围和执行方式：引用已有授权、项目入口与公共测试边界，记录实际 Skill/方法、版本或可取回来源及本地适配；任务生成不启动实施。

检查交接：必须按 [Run Task Checks](../references/task-checks.md) 在生成或更新任务后、交接前检查，执行者状态回写后也运行；填入实际产品/项目/目标命令、结果记录位置、退出结果及未检查范围。失败、未运行及旧格式按该指引处理，检查通过不等于交付或验收通过；跨机器接手重新解析产品路径。

## T1 Deliverable

- state: pending
- blocked_by: []
- rules: ["spec.md#<真实规则锚点>"]
- acs: []
- questions: []

- 交付：本任务可观察的结果摘要。
- 边界：引用 SPEC 范围/禁止项，补充允许触及与必要排除项；文件清单不扩大授权。
- 验证：说明公开边界、方法/命令及相关场景；业务阈值与预期从 SPEC 读取，测试和文档随本任务交付。
- 结果：未执行；执行后记录候选、实际检查、证据及缺口，规格变化保留原始结果与重核理由。

按真实交付继续列任务，保留旧任务 ID/依赖/历史；不按文件层次强造任务。五字段各一次，rules/acs/questions 至少一项非空；从实际 SPEC 填入并删除占位符，无项填 []。前置任务用 questions 的问题/判据配对，不伪造功能 AC。格式及失败处理见上述指引，完整业务规则不复制到任务正文。
