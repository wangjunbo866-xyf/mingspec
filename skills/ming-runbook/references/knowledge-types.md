# Knowledge Types

选择能减少重复错误或无效调查的经验与过程决定；业务需求和验收回 SPEC，单次日志和检查结果留原任务，避免会话抄录、流水账或无依据建议。

| 类型 | 默认正文 | 值得记录的内容 |
| --- | --- | --- |
| pitfalls | PITFALLS.md | 容易重复犯的错误、出现条件、避免方式和已验证修复；入口固定可达 |
| incidents | INCIDENTS.md | 事故影响、关键时间线、原因与恢复中学到的教训；不是告警全文 |
| decisions | DECISIONS.md | 已确认选型/工程约定的背景、备选、取舍、适用范围和重审条件；业务条款链接 SPEC |
| checklists | CHECKLISTS.md | 有依据的复用检查步骤及通过条件，说明在什么操作前后使用 |
| releases | RELEASES.md | 发版中发现的兼容、升级/回退和验证经验；记录发布与执行发布是两件事 |
| monitoring | MONITORING.md | 哪些信号能识别问题、阈值依据、误报经验及响应边界 |
| operations | OPERATIONS.md | 已验证且可复用的操作方法、前置条件、成功/失败判据与恢复方式 |
| troubleshooting | TROUBLESHOOTING.md | 从现象逐步排除问题的诊断路径和证据，避免未经验证的万能处方 |

相同主题更新同一条目，通常只放一个主要类型，其他类型链接它。例如事故详情留 incidents，提炼出的普遍防错规则可在 pitfalls 摘要链接，避免双份全文。仅当现有条目/章节无法承载长期知识时新增文件，不为一次维护新建目录、分类或汇总页。八种类型按需建立，不建八份空正文；空初始化只要求 PITFALLS 固定入口，不宣称已具备八类实际知识。

每条写清适用范围、学到的结论、原因/取舍、避免或复用方法、实际验证状态和来源。可用一个英文主题标题和简短中文正文，保留日期、适用环境及关键依据；字段多少由实际内容决定，不为凑模板编造根因、数字、时间线或检查结果。没有运行的检查不写成通过，未经确认的推断不升级为项目约定；明确要求保留的待验证事项标明状态。
